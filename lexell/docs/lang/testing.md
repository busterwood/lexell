# Adding and running tests

How to put a test in the right suite, what its comments mean, and which runs a
change needs. The full format and the coverage tables are in
[tests/README.md](../../tests/README.md); the gate is
[tools/gate.sh](../../tools/gate.sh). Run commands from the repository root.

## Which suite

| Put the test in | When it checks | Name it |
|---|---|---|
| `lexell/tests/run/`, `lexell/tests/error/` | a rule of the language ([SPEC.md](../../SPEC.md)): what a program prints or exits with, or which program is refused | `sNN_topic.lxl`, NN the SPEC section |
| `lexell/tests/compiler/run/`, `error/`, `unit/` | a compiler choice or a runtime limit that the spec leaves open. `unit/` tests are built through C with `// cflags:` (`-DRT_STR_MAX=64` lowers a limit) | the topic |
| `lexell/lib/tests/run/`, `error/` | a library module: behaviour, or the error for a misuse of its API | `module_topic.lxl` (`task_any_cancel`, `par_map_basic`) |
| `lexell/tests/lexdb/run/` | lexdb, the SQL server (`cmd/lexdb*.lxl`) | `tier_topic.lxl`; the tier is `store`, `exec`, `wire`, `tds` or `tns` |

A compiler bug gets a `tests/run` or `tests/error` test when the spec says
what is right, and a `tests/compiler` test when it does not. Helper modules for
library tests are in `lib/tests/support/`. `tests/native/` holds programs that
link C libraries through the native backend's dynamic linking; `run_native.py`
runs them, `run.py` does not.
A lexdb feature is tested in every dialect that has it: `exec_*` tests run SQL
through the PostgreSQL session, `tds_*` through SQL Server's protocol and
`tns_*` through Oracle's. Several `exec_*` tests are generated by
`tests/lexdb/gen_pg.py` from `*_queries.txt` files, with PostgreSQL's answers:
change the queries file and regenerate, do not edit the test.

## A test is a program with comments

A run test prints and exits; the runner compares them with its comments. These
two blocks are also checked by `tools/doc_check.py`, which reads the same
directives.

```lxl
// A trap stops the program with exit 3 after the earlier output.
fn at(xs: &[]int, i: int): int { return xs[i] }

fn main() {
    let xs: []int = [10, 20, 30]
    println(at(&xs, 2))
    println(at(&xs, 3))
    println("not reached")
}
// expect: 30
// exit: 3
```

An error test is a program the compiler must refuse. Name something distinctive
in the message (the offending variable or type) so that any sane wording
passes, and pin the line when the spot matters.

```lxl
fn main() {
    let zed = "a" + "b"
    let moved = zed
    println(zed)
}
// error: zed
// line: 4
```

| Directive | Meaning |
|---|---|
| `// expect: text` | one line of stdout, in order; stdout is compared exactly, and no `expect` line means empty |
| `// stderr: text` | one line of stderr; once a test has one, stderr is compared exactly |
| `// exit: N` | the expected exit code (default 0) |
| `// stdin: text` | one line fed to stdin |
| `// timeout: S` | seconds the run may take, over the default of 10 (30 for lexdb) |
| `// error: words` | the compile must fail and its output contain the words, in any case; `a\|b` accepts either; several lines must all match; empty accepts any failure |
| `// line: N` | the output must contain `:N:` |
| `// needs: name` | the test is skipped when no `libname.so*` is installed |

The runner builds with the native backend and runs the program in a fresh
directory, so a test may write files. A filter is a substring of the path
under the suite's directory: `s10_` or `error/s06` or `trap`.

## Multi-file tests, live tests, leaks

A directory that holds `main.lxl` is one test: `main.lxl` is compiled and
carries the directives, the other files are its modules (`import "./helper"`).
Use it for visibility rules and imports (`tests/error/s05_private_function/`).

A test that needs a database or another service exits 77 when the service is
missing, and has `_live` in its name. Every runner skips those by default so
that the gates stay hermetic; `--live` runs them, and they still report a skip
when the service is down. A test that exits 77 on purpose declares
`// exit: 77`.

Every run test runs under `LXL_CHECK=1`: objects still alive at exit make the
program exit 5, and the test fails. Run a program by hand the same way:

```sh
lexell/compiler/out/lxlc prog.lxl -o prog && LXL_CHECK=1 ./prog; echo $?
```

A leak in a test you wrote is a bug in the test or the compiler. Look for a
value stored in a global, an `rc` or `Shared` handle that was never dropped, or
a `drop` method that does not free what it owns.

## Running

```sh
flock -s ~/tpch/.bench.lock python3 lexell/tests/run.py -j 8 s10_
flock -s ~/tpch/.bench.lock python3 lexell/tests/compiler/run_tests.py [--conformance] [filters]
flock -s ~/tpch/.bench.lock python3 lexell/lib/run_tests.py -j 8 task_
flock -s ~/tpch/.bench.lock env LXL_NOCACHE=1 python3 lexell/tests/lexdb.py -j 4 exec_any
python3 lexell/tools/doc_check.py          # the lxl blocks of AGENTS.md and docs/lang/
```

The runners print one line per failure, then `N passed, M failed`, and exit 1
on a failure. Other sessions use this machine: test runs take the bench lock
shared (`flock -s`), so that a timing, which holds it exclusively, is not
disturbed. `LXLC=path` picks another compiler; one built outside
`compiler/out/` also needs `LXL_LIB=$PWD/lexell/lib` ([compiler.md](compiler.md)).

Always set `LXL_NOCACHE=1` for lexdb tests. The runners build natively unless
`LXL_CC` or `LXL_CACHE` is set (see tools/cbuild.py); with either set a lexdb
build goes through gcc and takes minutes. `lexdb.py` first checks the module
dependency rule (`tests/lexdb/imports.py`), then groups single-file tests by
tier into bundled binaries (50 to a binary, `--no-bundle` builds each alone).
A test with `// needs:`, a call of `args()`, a directory of files or a `main`
that is not written `fn main() {` is built on its own.

## The gate tiers

| Command | Runs | Use it |
|---|---|---|
| `lexell/tools/gate.sh quick` | the seed's fixed point (it also rebuilds `compiler/out/lxlc`), `tests/run.py`, the compiler tests, the library tests, `doc_check.py`, the borrow check, the native backend against the C backend (also with `-O`, and with `LXL_URING=0`), the native self-build | after every change |
| `lexell/tools/gate.sh full` | quick, then red-team rounds 1 to 5 and the task, net, proc, url, http, pgwire, redis and regex tests under ASan and UBSan, the helper-pool and net tests under TSan, the native backend on the red-team corpora and on generated programs, the HTTP generators and the regex comparison with Go | before a merge, and at the end of a fix round |
| `lexell/tools/gate.sh live` | the `*_live*` library tests and the native backend on them | when the database servers and Redis are up |

The gates are not for iterating: they take minutes, and quick fails until a
compiler change is reseeded. Run the suite you changed, then the gate. The
gate does not run the lexdb suite, `eza_gate.py`, `tools_gate.py` or
`zoxide.py`; run `lexdb.py` for a lexdb change and the others for a change to
`cmd/eza.lxl`, `cat`, `grep` or `zoxide` (tests/README.md).

## Generators and comparison tools

These sit outside the quick gate, or inside the full one. They use the C
backend and gcc as the oracle, which is why they are the gate's steps and not
your edit loop.

| Tool | Checks | Run it |
|---|---|---|
| `tests/run_prev.py` | the new compiler against a previous build: both must fail alike, or print and exit alike, on every run and error test (`--lib`, `--redteam`, `--gen N`, `--eza` add more) | when a compiler change is meant to keep every program's behaviour (an optimisation, a refactor): `LXL_PREV=old/lxlc python3 lexell/tests/run_prev.py --native` (`--native` keeps gcc out of it) |
| `tests/vrgen.py -n N --seed S` | generated programs that pass value records with heap fields around, built three ways, equal output | after a change to inlining, record rewrites or `-O`'s load reuse (`opt.lxl`, `cse.lxl`) |
| `tests/loopgen.py -n N --seed S` | generated array loops, many ending in a trap | after a change to the loop pass (`loops.lxl`) |
| `compiler/fuzz.py -n N --seed S` | mutants of every test program must compile or fail with one `file:line: message`, never crash or leak; failures go to `--keep DIR` (default `compiler/out/fuzz/`) | after a change to the parser, sema or the body checker |
| `redteam/rt.py` and `round2` to `round5/rt.py` | an independent review's cases under ASan, UBSan and `LXL_CHECK=1`; output classes `OK`, `ASAN`, `LEAK`, `CRASH`, `MISMATCH`, anything but `OK` fails | in the full gate; add a case (a `.lxl` with directives) when a review finds a bug, and name it for the finding |
| `tests/httpgen.py`, `httpsrvgen.py`, `regexgen.py` | the HTTP client and server and the regex library against reference implementations | after a change to those modules |

`vrgen.py` and `loopgen.py` print their seed: rerun it with `--seed S` to get
the same programs. Their failing programs are kept in `--keep DIR`.
Notes on what each red-team round found are in `redteam/FINDINGS.md` and
`redteam/round*/FINDINGS.md`.

## Before you say it is done

- The test fails without your change and passes with it.
- The suite for the area passes, then `gate.sh quick`; `gate.sh full` before a
  merge.
- A language change touches `SPEC.md`, the compiler and the tests together
  ([compiler.md](compiler.md)); `doc_check.py` fails when a documented
  example stops compiling.
